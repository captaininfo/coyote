Prerequisites

For Coyote to track and analyze your learning data, the **Browser Extension** and the **Core services** (Coyote Core + Neo4j) must be running. To use the chat assistant and NL→Cypher, also start the **Agent/Bot** and **Ollama/LLM** services.

Software

  • Docker Desktop/Engine + Compose v2
  • Python 3.10+
  • Firefox (temporary add‑on flow in 0.4)

Hardware

  • 8 GB RAM minimum for Core (Neo4j + Coyote Core)
  • 16 GB RAM recommended if running Agent + LLM
  • ~8–15 GB free disk (first‑run images, Neo4j data, optional model cache)

Ports (defaults)

  • UI: 8080
  • Coyote Core API: 5000
  • Neo4j HTTP/Bolt: 7474 / 7687
  • Ollama: 11434
  • Agent/Bot: 8501

If a port is taken on your machine, edit compose/.env then click Restart Services in the UI.

First run: the UI will create compose/.env (chmod 600) with sensible defaults and a random Neo4j password. Keep it private.

Coyote Configuration: Neo4j

Neo4j is the graph database where your personal learning record is stored. Configure credentials from the UI.

  1. Open Configure → Neo4j Database in the left sidebar.
  2. Neo4j URI: leave as bolt://localhost:7687 unless you changed ports.
  3. Enter a unique Username and Password to keep your data private.
  4. Click Test Connection. If you see “Unauthorized”, verify the values against compose/.env.
  5. Click Save. If Core is already running, click Restart Services (or Stop All → Start Core) so all services pick up the new credentials.
Behind the scenes, the Compose services use the internal URI bolt://database:7687. The UI writes your auth to compose/.env and also applies it to the running Core app.
Success check: On System Status, Neo4j and Coyote Core indicators turn Online/green. You can also open the Neo4j Browser from Explore Visually.

Coyote Browser Extension (Firefox)

The extension records search intent, SERP visits, pages read, and connects them to annotations. In 0.4 you’ll load it as a temporary add‑on.

  1. Open a new tab and go to about:debugging#/runtime/this-firefox.
  2. Click Load Temporary Add‑on….
  3. Select Coyote_0.4/extension/manifest.json.
  4. Keep this tab open while testing; temporary add‑ons unload when Firefox restarts.
Success check: On System Status, “Browser Extension” turns Online/green within a few seconds (heartbeats drive the status).

Docker Services

Most of Coyote runs in containers. Use the UI’s System Status tab to start/stop services by profile.

Start Core Services (Coyote Core + Neo4j)

  1. Open the System Status tab.
  2. Click Start Core Services. On first run, Docker will pull images—this can take a few minutes.
  3. Watch the health indicators near the top; they turn Online/green when ready.

Core is required for logging and analysis; pair it with the extension for recording to work.

Start All Services (Core + Agent + Ollama)

  1. Open the System Status tab.
  2. Click Start All Services. On first run, the LLM service pulls the configured model.
  3. Indicators for Core, LLM, and Agent turn Online/green when everything is ready.
The default model in Compose is mistral:7b-instruct (configurable). You can also start only the LLM via Start LLM Service.
Success check: “Open Coyote Search” works without the LLM, but the Chat Assistant and NL→Cypher require the LLM and Agent.

Hypothes.is Integration

Hypothes.is is an annotation service. Connecting your account lets Coyote import your highlights and notes and link them to the pages and concepts in your graph.

What it does

  • Imports your annotations (public and your private ones accessible via your token).
  • Creates Annotation nodes linked to their Webpage via HAS_ANNOTATION.
  • Annotations and pages are associated to WikiDataOntology topics via HAS_TOPIC when NLP analysis yields entities/topics.

Connect your account

  1. Open the Integrations tab and toggle Hypothes.is on (reveals its config panel).
  2. Find your credentials:
    • Username: visit https://hypothes.is/users/ (shown on your profile).
    • API token: visit https://hypothes.is/account/developer and generate a token.
  3. Paste Username and API token into the fields.
  4. Click Test. A success message confirms the token is valid.
  5. Click Save. The UI stores the values for the Core service (token stored encrypted in Core’s config; also written to compose/.env for service restarts).
  6. Click Fetch Data to start an import. If Core is running, the request is forwarded immediately.
Treat your token like a password. Do not commit compose/.env to source control. To rotate, generate a new token on Hypothes.is, update it in the UI, and click Save.
Success check: Open Explore Visually and run “Recent annotations → pages”. You should see your Annotation nodes linked to Webpages; topics may appear as red WikiDataOntology nodes when NLP has run.

Troubleshooting

Port conflicts

If a service won’t start and logs mention an address in use:

  1. Edit the relevant port in compose/.env (e.g., NEO4J_HTTP_PORT, NEO4J_BOLT_PORT, COYOTE_PORT, OLLAMA_PORT, BOT_PORT).
  2. Click Restart Services (or Stop All → Start…).

Containers won’t stop / zombie processes

On System Status first use Stop All Services. If anything is still “Up”, click Force Cleanup (Emergency).

Neo4j “Unauthorized” on Test

  • Re‑enter credentials on Configure → Neo4j Database and click Save.
  • Click Restart Services so Core/Agent reload the new auth.

LLM service “starting” for a long time

The first run downloads the selected model. This can take a while depending on bandwidth. Once the model exists, health turns green quickly on subsequent starts.

Browser Extension shows “Offline”

  • Reopen about:debugging#/runtime/this-firefox and ensure the temporary add‑on is loaded.
  • Reload the add‑on after a Firefox restart (temporary add‑ons do not persist). The indicator should turn green within ~10s.

Have a persistent issue? From a terminal run docker compose logs > logs.txt in the compose/ folder and attach it to a GitHub issue.
