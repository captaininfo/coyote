Coyote Roadmap

Transparent by design. This page outlines what we’re building now, next, and later — with clear outcomes, milestones, and contribution paths that a solo developer can execute.

Now Next Later

Now In progress

Fine-tune TF-IDF scoring

NLP Quality

Why: More meaningful topic ranking improves “aboutness,” reduces noise, and sets a reliable baseline before adding embeddings.

  • Approach: Lemmatization + better stoplists; per-domain weighting; time-decay option; evaluate against a small labeled set.
  • Milestones: M1 calibrate stopwords; M2 implement per-context TF-IDF (page vs. session); M3 add tests + docs with examples.
  • Definition of Done: ≥20% reduction in low-value topics vs. baseline on test corpus; reproducible notebook + docs.

Contribute: component:nlp • good first issue • add sample queries to /examples.

Improve phrase detection (multi-word expressions)

NLP

Why: Phrases like “open recognition” or “knowledge graph” carry meaning lost in unigram tokenization.

  • Approach: spaCy noun-chunking + phrase merger (configurable), optional RAKE/YAKE, PMI bigram/trigram fallback; align to Wikidata surface forms when available.
  • Milestones: M1 noun-chunks in pipeline; M2 phrase whitelist/blacklist config; M3 evaluation notebook + examples.
  • Definition of Done: Phrases appear as first-class topics/entities with stable IDs and are queryable in Neo4j.

Contribute: propose a phrases.yml config; add tests; update docs.

Thresholds for topics & entities

NLP Data Hygiene

Why: Recording everything increases storage and noise. Thresholds keep the graph lean and more interpretable.

  • Approach: Configurable TF-IDF and score cutoffs per context (page/session/global), with audit logs of filtered items.
  • Milestones: M1 global cutoffs; M2 per-context overrides; M3 UI/CLI to preview what would be kept vs dropped.
  • Definition of Done: Thresholding reduces nodes/edges by ≥25% while preserving top-K topics per page.

Contribute: add CLI flag + docs; create “before/after” graph screenshots for README.

Watched folder ingestion

Ingest PKM

Why: Many users keep notes or exports locally. A “drop files here” folder makes adoption simple without OAuth.

  • Approach: File watcher (e.g., watchdog) for a user-chosen directory; parse .md/.txt/.html first; PDF later.
  • Milestones: M1 detect & hash new/changed files; M2 extract text + metadata; M3 write events → SQLite → Neo4j.
  • Definition of Done: Files dropped in the folder appear as Webpage/Document nodes within 10s and are searchable by topic/entity.

Contribute: schema note for Document nodes; example notebook; error handling for large files.

Next Planned

Vectorize input & output data (embeddings)

NLP AI

Why: Embeddings let us correlate what you consume (inputs) with what you produce (outputs), enabling similarity search and input→output tracing while treating the mind as a black box.

  • Approach: Local embedding models only (configurable); chunk & embed inputs (visited pages, annotations) and outputs (notes, drafts). Store vectors as properties plus a sidecar ANN index (e.g., FAISS/HNSW). Keep metadata in SQLite/Neo4j.
  • Milestones: M1 input embeddings MVP; M2 output embeddings MVP; M3 similarity queries (top-k) + correlation report; M4 optional graph edges like :INFLUENCED_BY with score.
  • Definition of Done: Demo notebook: “show the five inputs most similar to this output,” all local, no cloud calls.

Contribute: add config schema; benchmarking notebook; UX copy for “explain the match.”

Platform integrations

Ingest Ecosystem

Why: Meet users where their data already lives. Start with low-friction paths before OAuth/API complexity.

  • YouTube: MVP via exports (Takeout/watch-history JSON) → title, channel, timestamps, topics/entities; API optional later.
  • Obsidian: Use the watched folder first (Markdown); optional community plugin later for richer metadata.
  • Google Drive (Docs/Sheets/Slides): Begin with manual exports to watched folder; consider Drive API once auth UX is clear.
  • X (Twitter): Start with archive import (user export ZIP); live API integration is a later, optional step.
  • Reddit: Start with personal data request export; map posts/comments to events with topics/entities.
  • Other: Add connectors as separate modules in data_sources/ to keep Coyote modular.

Contribute: draft import specs; add sample anonymized exports for tests; write per-source README files.

Prompt hardening (for optional AI features)

AI Security

Why: If/when users connect local LLMs/agents, we need patterns that resist prompt injection, ensure schema-valid outputs, and never leak private data.

  • Approach: System prompts that describe the local-only policy; JSON schema enforcement; tool/result whitelisting; redaction of sensitive fields before any model call.
  • Milestones: M1 shared prompt library; M2 JSON-only responses + validators; M3 unit tests with adversarial cases; M4 docs on safe patterns.
  • Definition of Done: Example flows pass adversarial tests and keep all processing local by default.

Contribute: add adversarial test cases; propose guardrail patterns; update docs with “secure by default” checklist.

Later On the horizon

Richer API connectors (Drive, YouTube, Reddit, etc.)

Ingest

Why: After proving value with exports and watched folders, full APIs unlock incremental sync and richer metadata.

  • Approach: OAuth flows gated behind clear consent UI; incremental sync; back-off & quotas; robust error handling.
  • Definition of Done: Reliable sync for at least one major provider with offline cache and resumable progress.

Embedding-driven “Explain my week” views

AI UI

Why: Turn similarity/search into digestible insights: clusters, shifts in topics, and input→output narratives.

  • Approach: Lightweight, local summaries over top-K items; privacy-first annotations; export to Markdown.
  • Definition of Done: One screen and one export that a user can run weekly without config.

Contributing

We keep issues labeled by component (component:nlp, component:ingest, component:graph, component:ui, docs) and difficulty (good first issue, help wanted). Start with docs or tests, then pick a scoped module in data_sources/ or the NLP pipeline.

  • Definition of Done: tests passing, docs updated, reproducible steps, privacy notes included.
  • Ethos: local-first, no phoning home, transparency over black boxes.
